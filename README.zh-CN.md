# Prompt optimizer

[English](README.md)

[![许可证：BSD 3-Clause](https://img.shields.io/badge/License-BSD--3--Clause-blue)](LICENSE)
[![DeepSeek Harness bundle 插件](https://img.shields.io/badge/DeepSeek_Harness-Bundle_plugin-2563eb)](#安装)

一个适用于 DeepSeek Harness（DSH）的提示词优化插件。在消息框旁新增一个按钮，点击后用对话模型或专用模型重写草稿。缺少必要信息时会先向你追问。

插件会读取当前会话，按设置用 AI 摘要或本地压缩整理成有界上下文，一并交给优化模型，因此在**对话中途**同样可用，而不局限于开场。

## 功能

- **消息框旁的按钮**：位于 composer 工具行，点击打开优化弹窗。
- **优化**：把草稿交给模型重写。
- **缺少信息时追问**：最多 4 个具体问题；可以只答一部分，也可以「跳过，直接优化」。
- **结果可编辑**：可直接改，再「插入输入框」（写回 composer）或「复制」。
- **两种输出形态**：见下文。
- **会话上下文**：自动读取本会话消息并压缩，供优化模型参考。
- **上下文默认值**：在插件设置里决定默认是否带上下文、以及用 AI 摘要还是本地压缩；弹窗里点草稿上方的上下文图标只改这一次。

## 两种输出形态

优化器根据草稿性质选择形态，并在结果标题旁标注：

| 形态 | 适用 | 规则 |
|---|---|---|
| **完整提示词** | 会话与该任务无关 | 角色、目标、上下文、交付格式、硬约束，自包含 |
| **增量指令** | 后续、修订、纠正、下一步 | 不重述身份与背景；只写这次改什么；仅在约束必须继续成立、有风险或被强调时重申 |

关闭「参考本会话上下文」后没有历史可判，一律产出完整提示词。

## 会话上下文与摘要

- 通过宿主的 `ctx.sessions.get(sessionId)` 取当前活动会话，再用 `Session.deriveMessages()` 读模型实际看到的消息列表。
- 上下文只使用用户和助手的可见文本，过滤会话系统提示、DSH 压缩检查点、工具调用和结果、推理及附件。
- 默认使用 AI 摘要：多一次模型调用，保留目标、约束、决定和待办。可在插件设置里改为本地压缩，不额外调用模型。
- 历史本身未超出 `maxContextChars` 时直接原样带上，不触发摘要调用。
- 摘要失败或超时时，回退到本地压缩继续优化。
- 同一会话的历史和模型设置未变时复用摘要。宿主内存最多缓存 32 条成功的摘要，每条保留 30 分钟。相同的并发请求共享一次摘要生成。
- 弹窗会显示本次使用的来源：AI 摘要、缓存摘要或本地压缩。

## 安装

本插件是本地 bundle，`private: true`，不发布到 npm。

在 DSH 中通过 **Plugins → Add plugin** 选择本目录，或由智能体执行 `plugin_manager` 的 `install_bundle`（target 为本目录绝对路径）。

安装后无需重启，客户端模块会热加载；若界面未更新，刷新页面即可。

## 配置

在 DSH 的 **插件 → 提示词优化** 详情页选择优化时使用的模型和上下文默认值，然后点击 **保存**。

- **使用对话模型**（默认）沿用当前会话的模型选择。新会话没有单独选择时，使用 DSH 的默认模型。
- **使用优化专用模型** 从 DSH 模型目录选择一个固定模型，应用于所有会话的优化请求。草稿和启用的会话摘要会发给该模型提供方。
- **会话上下文** 决定新请求默认是否带上下文，弹窗仍可单次关闭或开启。
- **上下文整理方式** 选择默认用 AI 摘要（多一次模型调用）还是本地压缩（不额外调用）。弹窗里的上下文图标只影响这一次请求，不会保存。

已有的 `provider` 和 `model` 固定配置会沿用为专用模型，直到从插件设置切换模式。

同一页还设置 **上下文预算**（6,000 / 12,000 / 24,000 字）和 **请求超时**（30 / 60 / 90 / 180 秒）：两者同时作用于摘要和优化调用；如果配置里已有预设之外的值，它会作为一个可选项保留。

插件行配置还支持下列参数。

| 字段 | 默认 | 说明 |
|---|---|---|
| `timeoutMs` | `90000` | 摘要与优化共用的请求超时（毫秒） |
| `maxContextChars` | `6000` | 摘要输入及发给优化模型的会话上下文字符上限，最高 `24000` |
| `contextDefault` | `on` | 新优化请求默认是否带会话上下文：`on` 或 `off` |
| `summaryMode` | `ai` | `ai` 用一次额外模型调用生成摘要；`local` 用本地压缩，不额外调用 |

## 工作原理

- **宿主半部**（`index.js`）注册一个 `POST /prompt-optimizer/optimize` 端点，负责读会话、压缩、调用 `ctx.llm`，并返回 `{ok, stage, prompt|questions, shape, notes, context}`。
- **浏览器半部**（`client.js`）通过 `window.__ModuleLoader__` 注册 `conversation.input.left`（按钮）、`shell.overlay`（弹窗）和 `plugins.bundle.config`（插件设置）。
- 界面样式使用宿主的 `--dsw-alias-*`、`--dsw-radius-*`、`--dsw-font-*`、`--dsw-elevation-*` 设计令牌，跟随明暗主题与用户字号。

## 限制

- 需要一个已选中的模型路由，没有时请求会被拒绝并给出说明。
- 草稿超过 20,000 字符会被拒绝。
- 非活动会话（例如未打开过的冷会话）不提供上下文，请求退化为仅用草稿。
- 弹窗覆盖在对话之上，不新增标签页或侧栏页面。
